# 工具调用指引

`@local/dsh-tool-call-guidance` 1.1.0：让模型在每次调用前选对工具并构造正确参数，覆盖首次调用与后续步骤。

## 核心规则

1. 按当前意图选择准确的工具和操作。
2. 只传必填项和有意使用的可选项；检查类型、互斥、依赖及字段存在性。
3. 发送前核对最终工具名、参数对象和当前作用域内的标识；先解决缺值与接口冲突。
4. 每次重查；会话权限、工具契约、作用域或相关状态变化时更新依据。按新意图重建参数，不复制旧调用。
5. 根据真实结果推进；诊断后再重试，异步启动后收集完成结果。

无用字段省略；保留有意使用的 false/0；不填空值凑参数。

## 持续生效与简练

插件直接把主 `tool-call-planning` skill 的短正文注册为常驻系统提示，每轮提供同一套规则，避免首次加载后逐渐遗忘，也避免维护两份不同的规则。已经在上下文中的正文无需重复读取。

子智能体调用前加载短 `subagent-routing`；DSH 的筛选与路由示例按需读取各自 `references/`，在契约有效时复用。工具、权限或状态变化后只补查变化的信息，不要求每次额外发现或探测。

插件只使用 `skills`、`systemPrompt` 服务，没有运行时拦截、参数改写或自动重试。指引不能修复宿主强制错误参数形状的问题；遇到签名冲突，应在执行前找到合法形式或报告具体限制。

## 安装

通过 DSH `plugin_manager` 安装插件压缩包并启用。按返回的 `application`、`warnings`、`nextStep` 判断是否即时生效，随后实际读取 skill 验证。使用包安装时，开发目录与运行版本分离，可在开发副本验证后更新安装；直接链接源码时先停用再修改。

单独使用时，把完整 skill 文件夹及 `references/` 放进宿主支持的目录。要覆盖长会话和上下文压缩后的调用，还应把主 skill 的短正文放进该宿主的持久项目指令或系统指令层；仅安装可发现的 skill 不等于其正文始终在上下文中。DSH 插件已自动完成此步骤。

## 验证

Node.js 22+，无第三方运行时依赖或安装脚本。`npm test` 检查资源、必填注册元数据、释放与重新激活，以及常驻提示和主 skill 正文一致。运行时验证与模型成功率分别记录，不把参数规划正确等同于实际执行成功。
